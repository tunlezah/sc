# Deliverable 6: AVRCP Media Controls

## Overview / Goal

Read track metadata (title, artist, album, duration) and send playback commands (play, pause, next, previous) to the connected Bluetooth device using AVRCP via BlueZ's `org.bluez.MediaPlayer1` D-Bus interface.

## Technical Approach

Use a `zbus` proxy to access `MediaPlayer1` properties and methods. Poll at adaptive intervals (250ms when active, 2000ms when idle). Cache the proxy per device to avoid per-poll D-Bus overhead and lifetime errors.

## Key Data Structures

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct TrackInfo {
    pub title: String,
    pub artist: String,
    pub album: String,
    pub duration_ms: u64,
    pub track_number: Option<u32>,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum PlaybackStatus { Playing, Paused, Stopped, Unknown }

// zbus 4.x proxy (client side -- #[proxy] not #[interface])
#[proxy(
    interface = "org.bluez.MediaPlayer1",
    default_service = "org.bluez",
    gen_blocking = false
)]
trait MediaPlayer1 {
    fn play(&self) -> zbus::Result<()>;
    fn pause(&self) -> zbus::Result<()>;
    fn stop(&self) -> zbus::Result<()>;
    fn next(&self) -> zbus::Result<()>;
    fn previous(&self) -> zbus::Result<()>;
    #[zbus(property)]
    fn status(&self) -> zbus::Result<String>;
    #[zbus(property)]
    fn track(&self) -> zbus::Result<HashMap<String, OwnedValue>>;
}

pub struct AvrcpMonitor {
    connection: zbus::Connection,
    state: AppStateHandle,
    cached_proxy: Option<(String, MediaPlayer1Proxy<'static>)>,
    poll_interval: Duration,
}
```

## Step-by-Step Implementation Tasks

1. Define `TrackInfo` and `PlaybackStatus` structs with serde derives.
2. Define `MediaPlayer1Proxy` using `#[proxy]` macro (zbus 4.x).
3. Implement `AvrcpMonitor` with adaptive polling loop.
4. Implement proxy caching (store `(address, proxy)` tuple).
5. Implement `parse_track_info` from `HashMap<String, OwnedValue>`.
6. Implement change detection (cache last values, emit events only on change).
7. Implement command handling (play/pause/next/previous from web API).
8. Handle player unavailability gracefully.

## Known Pitfalls

| Pitfall | Mitigation |
|---------|------------|
| Lifetime errors with zbus proxies | Cache proxy in struct with `'static` lifetime. |
| `#[dbus_proxy]` vs `#[proxy]` | Use `#[proxy]` (zbus 4.x syntax). |
| Player path doesn't exist until streaming | Retry proxy creation on failure. |
| Some devices don't support AVRCP | Check UUIDs before attempting. |

## Acceptance Criteria

1. Track title/artist/album appear in web UI during playback.
2. Play/pause/next/previous from web UI control the phone.
3. Playback status reflected in real-time.
4. Empty/disabled state when no device connected.
5. Adaptive polling: 250ms active, 2000ms idle.
