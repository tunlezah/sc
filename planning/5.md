# Deliverable 5: WebRTC Audio Streaming (Opus)

## Overview / Goal

Stream live audio from the SoundSync device to any web browser using WebRTC with Opus encoding. This replaces the original WebSocket raw audio approach that caused Safari issues.

## Technical Approach

**Crate:** `webrtc 0.12` (pure Rust WebRTC stack). Also `opus 0.3` for encoding.

**Flow:**
1. Browser sends `webrtc_start` via WebSocket.
2. Server creates a `RTCPeerConnection`.
3. Browser creates an offer (`recvonly` audio) and sends via WebSocket.
4. Server sets offer, creates answer, sends back.
5. ICE candidates exchanged via WebSocket.
6. Server captures PCM from `soundsync-capture.monitor` via `pw-cat`.
7. Server encodes PCM to Opus (128kbps, 48kHz, stereo, 20ms frames).
8. Server sends Opus frames via RTP.
9. Browser plays via `<audio srcObject>`.

## Step-by-Step Implementation Tasks

1. Implement `OpusEncoder` wrapper (48kHz stereo, 128kbps, Audio application).
2. Implement `AudioCapture` (spawn `pw-cat`, read 960-sample frames, broadcast).
3. Implement `WebRtcManager` (build API, configure STUN servers).
4. Implement `create_session` (PeerConnection, audio track, ICE callback).
5. Implement `handle_offer` (set remote desc, create answer, start audio pump).
6. Implement `handle_ice_candidate`.
7. Implement `remove_session` (close PeerConnection, abort tasks, cleanup).
8. Extend WebSocket handler for signaling messages.
9. Handle lifecycle events (stream stop, service shutdown).
10. Handle multiple concurrent clients (shared broadcast, per-client encoder).

## Testing Strategy

- Unit test for OpusEncoder: encode sine wave, verify decodable output.
- Unit test for frame sizing: verify 1920 f32 values per frame.
- Integration test: WebRTC session exchange (mark `#[ignore]`).

## Known Pitfalls

| Pitfall | Mitigation |
|---------|------------|
| `pw-cat` not available | Fall back to `parec --raw`. Check both at startup. |
| Browser autoplay policy | Require user click before starting WebRTC. |
| `webrtc` crate API churn | Pin to `0.12`. Build PoC first. |

## Acceptance Criteria

1. "Listen" button starts audio in the browser.
2. Latency under 500ms (ideally 100-300ms).
3. Works in Chrome, Firefox, Safari.
4. Multiple clients can listen simultaneously.
5. Clean session cleanup on disconnect.
