# Deliverable 7: Line-In Audio Source

## Overview / Goal

Detect and use a physical line-in (3.5mm jack or USB audio interface) as an alternative audio source. When line-in is activated, Bluetooth audio is disconnected and the line-in source is routed through the same EQ/spectrum/WebRTC pipeline.

## Technical Approach

Detect ALSA input devices via `pactl list short sources` and look for `alsa_input.*` entries. Switch PipeWire routing by changing the filter-chain's capture source.

## File Structure

```
src/

}
```

## Step-by-Step Implementation Tasks

1. Implement source detection (`pactl list short sources`, filter for `alsa_input.*`).
2. Implement activation (disconnect BT, update filter-chain, update AppState).
3. Implement deactivation (revert filter-chain, do NOT auto-reconnect BT).
4. Wire API endpoints: `GET /api/line-in/status`, `POST /api/line-in/activate`, `POST /api/line-in/deactivate`.
5. Startup detection during initialization.

## Testing Strategy

- Unit test for source detection parsing.
- Integration test on system with line-in: mark `#[ignore]`.

## Dependencies

- **Depends on:** Deliverables 1, 3.
- **Depended on by:** Deliverable 4 (LineIn UI toggle).

## Known Pitfalls

| Pitfall | Mitigation |
|---------|------------|
| `pactl` output format varies | Parse conservatively with substring matching. |
| Source name changes on reboot | Re-detect on each activate request. |

## Acceptance Criteria

1. Line-in availability correctly detected and reported.
2. Activating line-in routes analog audio through EQ to speakers.
3. Spectrum analyzer and WebRTC work with line-in audio.
4. Activating line-in disconnects Bluetooth.
5. Deactivating line-in stops routing but doesn't auto-reconnect BT.
