# Deliverable 2: Accept Connections with SBC/AAC/LDAC/aptX/aptX HD Negotiation

## Overview / Goal

Register A2DP media endpoints with BlueZ for five codecs so that connecting devices can negotiate the best available codec. PipeWire's `spa-bluez5` plugin handles actual decoding; our role is to advertise capabilities and report which codec was selected.

## Technical Approach

Register separate `org.bluez.MediaEndpoint1` D-Bus interfaces at distinct object paths. Each endpoint provides codec capabilities as a byte blob. BlueZ performs capability intersection with the remote device and calls `SetConfiguration` on the winning endpoint.

**Endpoint paths:**
- `/org/soundsync/a2dp/sbc`
- `/org/soundsync/a2dp/aac`
- `/org/soundsync/a2dp/ldac`
- `/org/soundsync/a2dp/aptx`
- `/org/soundsync/a2dp/aptx_hd`

## Step-by-Step Implementation Tasks

1. Define `AudioCodec` enum and all associated methods in `codecs/mod.rs`.
2. Implement capability blobs for each codec. Reference BlueZ `a2dp-codecs.h` for byte layouts.
3. Implement `A2dpEndpoint` struct with `#[zbus::interface]` for `MediaEndpoint1`.
4. Implement `select_configuration` for each codec (intersect capabilities, pick best).
5. Register endpoints with BlueZ via `Media1.RegisterEndpoint`.
6. Handle `SetConfiguration` callback -- update AppState with codec, emit `StreamStarted`.
7. Handle `ClearConfiguration` callback -- emit `StreamStopped`.
8. Integrate with BluetoothManager from Deliverable 1.

## Testing Strategy

- Unit tests for capability blobs: verify byte lengths and known bit patterns.
- Unit tests for `select_configuration`: given remote capabilities, verify correct intersection.
- Integration test (requires BlueZ): mark `#[ignore]`.

## Known Pitfalls

| Pitfall | Mitigation |
|---------|------------|
| Vendor-specific codec blobs poorly documented | Use BlueZ source `a2dp-codecs.h` as canonical reference. Start with SBC only. |
| `spa-bluez5` may not support LDAC/aptX without libraries | Document required packages: `libldac`, `libopenaptx`, `libfdk-aac`. |
| Registering too many endpoints before SBC works | Register SBC first, validate e2e, then add others one at a time. |

## Acceptance Criteria

1. SBC endpoint registered and acknowledged by BlueZ.
2. Phone negotiates SBC and audio plays through PipeWire.
3. AAC works with iPhone. LDAC works with Android (when `libldac` installed).
4. Selected codec reported in `DeviceInfo.codec` and visible in web UI.
5. `SetConfiguration`/`ClearConfiguration` correctly update AppState and emit events.
