# Deliverable 4: Web UI (Preact + TypeScript + Vite)

## Overview / Goal

Build a responsive single-page web application for controlling all SoundSync features: Bluetooth device management, EQ controls, spectrum visualization, media playback controls, and WebRTC audio streaming. The UI communicates with the backend via REST API and WebSocket.

## Technical Approach

**Stack:** Preact (lightweight React alternative, ~3KB gzipped), TypeScript, Vite, CSS Modules.

**Color scheme:**
- Light mode: Blue `#4448FF`, Purple `#9652F5`, Light Gray background, White `#FFFFFF`
- Dark mode: Blue `#3380CC`, Purple `#7A44D4`, Dark Gray background, Black `#000000`

**Version display:** Visible version string (e.g. "v1.0.0") in the header/footer, purely cosmetic.

**Communication:**
- REST API: 18 endpoints per spec section 7.1
- WebSocket at `/ws/status`: state snapshot on connect, then real-time events
- WebRTC signaling piggybacked on the same WebSocket

## Key TypeScript Types

```typescript
export interface AppState {
  status: string;
  devices: DeviceInfo[];
  eq: { bands: EqBand[]; enabled: boolean };
  active_device: string | null;
  track_info: TrackInfo | null;
  playback_status: PlaybackStatus;
  line_in_active: boolean;
  line_in_available: boolean;
}

export type WsMessage =
  | { type: "state_snapshot"; data: AppState }
  | { type: "device_state_changed"; data: { address: string; name: string; state: DeviceState } }
  | { type: "eq_changed"; data: { bands: EqBand[]; enabled: boolean } }
  | { type: "track_changed"; data: TrackInfo | null }
  | { type: "playback_status_changed"; data: { status: PlaybackStatus } }
  | { type: "spectrum_data"; data: { bands: number[] } }
  | { type: "webrtc_answer"; data: { sdp: string } }
  | { type: "webrtc_ice_candidate"; data: RTCIceCandidateInit };
```

## Step-by-Step Implementation Tasks

1. Initialize project with `npm create vite@latest webui -- --template preact-ts`.
2. Implement `types.ts` matching Rust serde output (`snake_case`).
3. Implement `api/rest.ts` with typed fetch wrappers for all 18 endpoints.
4. Implement `api/websocket.ts` with auto-reconnect (exponential backoff, max 30s).
5. Implement `hooks/useAppState.ts` with state snapshot + incremental merge.
6. Implement `DeviceList` component with state badges and connect/disconnect/remove actions.
7. Implement `EQControls` with 10 vertical sliders (-12 to +12 dB), preset selector, debounced updates.
8. Implement `SpectrumVisualizer` with canvas rendering of 64 bands using `audioMotion-analyzer`.
9. Implement `MediaControls` with prev/play-pause/next and track info display.
10. Implement `AudioPlayer` with WebRTC "Listen" button.
11. Implement `api/webrtc.ts` for signaling (create PeerConnection, offer/answer via WS).
12. Implement layout, dark mode toggle, collapsible sections, responsive design.
13. Add version number display in Header component.
14. Build static files. Axum serves via `tower-http::services::ServeDir`.

## Known Pitfalls

| Pitfall | Mitigation |
|---------|------------|
| Safari AbortError on AudioContext | Use WebRTC `<audio srcObject>`, NOT AudioContext. |
| WebSocket reconnect storms | Exponential backoff with jitter, max 30s. |
| EQ slider generating too many API calls | Debounce 100ms on `onInput`, only send on `onChange` or after debounce. |
| Spectrum data overwhelming slow clients | Use `requestAnimationFrame`, drop frames if behind. |

## Acceptance Criteria

1. `npm run build` succeeds. `npm run lint` passes. `tsc --noEmit` passes.
2. UI loads without console errors in Chrome, Firefox, Safari.
3. Device list shows correct state badges. EQ sliders work with debouncing.
4. Spectrum visualizer renders smoothly. Media controls work.
5. WebRTC audio player starts and stops correctly.
6. Dark/light mode toggle works. Colors match brand palette.
7. Responsive layout: usable on desktop (1920px) and mobile (375px).
8. Version number visible in the UI.
